# Security Policy — Mettelo Resource Hub

The Mettelo Resource Hub contains published educational material and privately maintained source documents. **Do not use public issues to report exposed credentials, private files, personal information or exploitable vulnerabilities.**

## Reporting concerns

If you find exposed secrets, sensitive information, unsafe instructions or an access-control problem, contact the repository administrator through a **private, authorised Mettelo communication channel**. Confirm the channel through https://mettelo.com/ if necessary. If GitHub's **Private Vulnerability Reporting** is enabled, use that feature.

Include the affected path, nature of the issue, and enough non-sensitive detail for a maintainer to investigate. Do not attach another person's passport, customer database, credentials or full sensitive record.

## Administrator response

- **Credentials:** revoke/rotate compromised keys promptly; deleting one file does not remove an exposed secret from Git history or copies.
- **Personal data:** limit access, assess exposure and follow applicable privacy/incident processes.
- **Incorrect public guidance:** amend the current resource and notify relevant readers when the consequence is material.
- **Repository access:** review collaborators and installed apps, use least privilege and recheck forking/visibility/branch rules.

## Publishing boundary

The main repository is intended as a **private editorial source**. Do not deploy all repository contents or expose repository tokens to browser-side code. A website should publish **only approved, sanitised resources** through a controlled process.
