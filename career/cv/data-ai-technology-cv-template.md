## How to use this template

1. Read the [CV Development Workflow](cv-development-workflow-edition-3.md) and prepare truthful, role-by-role evidence.
2. Read the actual job advert; select relevant tools, responsibilities, outcomes and qualifications.
3. Copy the **CV template** below into your preferred editor. Replace every placeholder, delete example lines that do not apply, and maintain genuine chronological details.
4. Prefer a simple single-column structure for online applications unless the employer asks otherwise. The previous Word sidebar version remains available through Git history **only as a historical design reference**; it is not a separate current guide.
5. Review the completed CV for accessibility, privacy, required credentials, reading order and the vacancy's file/AI-use instructions.

# [YOUR FULL NAME]

[Target role or specialism — optional]  
[Professional phone] · [Email] · [City/region, country if useful] · [LinkedIn] · [GitHub/portfolio if relevant]

### Professional profile

[Two to four evidence-led lines: your current professional level and specialism; which real systems, users or problems you have worked on; two or three relevant, demonstrated capabilities; and the kind of result you can substantiate. ### Selected achievements (optional)

Use **only when** the achievements are relevant, distinct and supported. Otherwise, lead with your experience.

- [Action personally performed] using [actual method/tool] for [real project/users], resulting in [confirmed outcome].
- [Important decision or problem solved], with [real quality, cost, reliability, service, accessibility or adoption result].
- [Meaningful collaboration/leadership] that led to [confirmed deliverable, decision or standard].

### Relevant technical expertise

Choose **only capabilities you can discuss or demonstrate**. It is better to show a few used tools than a long unverified catalogue.

| Area | Genuine skills and methods to include |
| --- | --- |
| Programming and software | [Python / R / Java / JavaScript / testing / APIs, as applicable] |
| Data and databases | [SQL / modelling / warehousing / quality checks / governance] |
| Data engineering | [Ingestion / ETL or ELT / orchestration / streaming / transformation] |
| AI and machine learning | [Modelling / evaluation / deployment / monitoring / responsible AI] |

| Delivery and communication | [Requirements / stakeholder engagement / research / coaching] |

**Tip:** In a final employer CV, a compact group of skills may be easier to read than this table. Remove unused rows and move high-priority skills near the role they support.

## Tailor the template by target specialism

| Target role | Evidence to prioritise | What to avoid |
| --- | --- | --- |
| Data analyst / BI analyst | Data grain, checks, reporting model, audience, analysis decisions and confirmed service/business use | Listing visualisation tools without describing work |
| Data engineer / analytics engineer | Sources, transformations, orchestration, testing, reliability, lineage, scale where real | Claiming architecture ownership if you only supported it |
| Data scientist / ML engineer | Research question, train/evaluation design, baselines, uncertainty, deployment and monitoring where performed | Stating model accuracy with no data or evaluation context |
| Software engineer | Features, interfaces, tests, review, performance, security, maintenance and users | Treating every technology in a tutorial as professional experience |
| Product/technical manager | Product problem, prioritisation, trade-offs, stakeholders, adoption and delivery outcome | Unsupported revenue/usage or people-management claims |
| Technical marketing / growth analytics | Experiment design, attribution, data governance, confirmed customer or commercial impact | Mixing ad-platform estimates with verified incremental outcomes |

### Former two-column Word layout: what was retained

The earlier visual design placed a short **Professional Focus**, technical skills, strengths, education and certifications in a sidebar, with profile, career highlights and work history in a main column. Those **content categories are retained here** in a single-column, Markdown-readable structure. If you create a designed Word CV later, you may apply sidebars as a **presentation choice**, provided reading order and employer requirements are satisfied. Do not attempt to replicate a two-column Word page by placing manually spaced columns in Markdown.

### Final submission checklist

- [ ] All placeholders, unnecessary rows and template instructions are removed.
- [ ] Job dates, titles, responsibilities, claims and qualifications are correct.
- [ ] Skills only show capabilities actually used, studied or credibly demonstrated, with exposure distinguished from experience.
- [ ] Numbers have a trustworthy source or have been removed.
- [ ] Confidential client, patient, employer, research or personal information is not exposed.
- [ ] Employer length, file type, anonymisation and AI-assistance rules are followed.
- [ ] Word/PDF rendering and selectable reading order have been checked where files are required.
- [ ] Portfolio and contact links work.
- [ ] The final CV reads as *your* professional experience, not as a template.
